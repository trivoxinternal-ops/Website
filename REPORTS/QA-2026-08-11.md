## 4. Hidden-Content / Mobile Bugs

**Status: ✅ Clean — well-architected reveal system**

### `[data-reveal]` — motion.js (IntersectionObserver)

- **Initial state:** `opacity:0; transform:translateY(26px)` — hidden
- **Threshold:** `0.15` — fires when 15% of element is visible ← **SAFE** (well below the risk threshold of ≥0.4)
- **rootMargin:** `'0px 0px -8% 0px'` — slight bottom offset, generous for mobile
- **Fallback:** If IntersectionObserver is unavailable, all reveals immediately `.add('in')`. If `prefers-reduced-motion` is set, same immediate reveal. ✅
- **Result:** No tall element stuck hidden on mobile. The threshold is appropriate.

### GSAP scroll.js (transform-only animations)

The code explicitly comments:
> "reveals animate TRANSFORM ONLY (no opacity). Opacity fade stays with motion.js [data-reveal], so nothing can ever get stuck invisible if a ScrollTrigger misfires."

GSAP ScrollTrigger start points:
- `.band .head` children → `start: 'top 82%'` — fires early as section enters viewport ✅
- `.feature` rows → `start: 'top 78%'` ✅
- `.ledger` rows → `start: 'top 84%'` ✅
- `.vault-in` → `start: 'top 70%'` ✅
- `.product` → `start: 'top 85%'` ✅

All triggers are generous. GSAP also calls `ScrollTrigger.refresh()` after `window.load` and after 700ms timeout, which handles layout shifts from fonts/images. ✅

### ⚠️ `<a href="#">` wrapping "Hours" text (4 pages)

```html
<span><span class="lbl">Hours</span><a href="#">Mon–Fri, 9–6 EST</a></span>
```

Found on: **index.html**, **ai-automation-toronto.html**, **ai-voice-agents.html**, **workflow-automation.html**

The hours text is wrapped in a non-functional `<a href="#">`. This is a `#` anchor that scrolls the page to the top on click — unexpected behaviour for "hours" text. Should be a `<span>` instead of `<a href="#">`. Low severity (cosmetic/UX), but it can confuse screen readers and causes a page-jump on mobile tap.
