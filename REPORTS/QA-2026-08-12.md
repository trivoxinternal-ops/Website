## 4. Hidden-Content / Mobile Bugs

**Status: ✅ CLEAN**

### `[data-reveal]` pattern (motion.css + motion.js)
- Elements with `[data-reveal]` start at `opacity:0; transform:translateY(26px)`
- IntersectionObserver in `motion.js` uses **`threshold: 0.15`** — well below the 0.4 mobile-risk threshold
- `rootMargin: '0px 0px -8% 0px'` slightly shrinks trigger zone — does not increase risk
- Fallback paths both work: `prefers-reduced-motion` immediately adds `.in`; no-IntersectionObserver support also immediately adds `.in`
- **No stuck-invisible risk on mobile**

### GSAP ScrollTrigger (index.html inline + scroll.js)
- The code comment explicitly states: *"reveals animate TRANSFORM ONLY (no opacity). Opacity fade is handled by motion.js [data-reveal]"*
- GSAP only animates `y`/`xPercent` — not opacity — so a GSAP misfires leaves content **visible**, just not slid in
- `ScrollTrigger.refresh()` called on `load` + after 700ms to handle font/layout shifts
- **No content can get stuck invisible due to GSAP**

### Vault section (index.html)
- `<section class="vault reveal">` — the `.reveal` class has only `will-change: transform,opacity` (no hidden state)
- Vault image (`ds/sign.jpg`) is an `<img>` tag, not CSS `background-image` — loads regardless of reveal state
- GSAP vault animation: `{y:52, scrollTrigger:{trigger:'.vault', start:'top 70%'}}` — triggers when vault top hits 70% viewport, safe on mobile
