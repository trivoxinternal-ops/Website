## 4. Hidden-Content / Mobile Bugs

**Status: ✅ CLEAN — pattern is safe**

### `[data-reveal]` pattern
- CSS: elements start at `opacity:0; transform:translateY(26px)`
- JS (motion.js): IntersectionObserver with **`threshold: 0.15`** and `rootMargin: '0px 0px -8% 0px'`
- On trigger: adds class `.in` → `opacity:1; transform:none`
- **Threshold is 0.15 (15%) — this is low and safe.** Even on tall mobile viewports, 15% of an element becoming visible is easy to hit.
- Fallback: if IntersectionObserver is unavailable, reveals all elements immediately.
- Reduced-motion: CSS rule forces `opacity:1 !important; transform:none !important; transition:none` — safe.

### GSAP / ScrollTrigger (index.html and sub-pages)
- GSAP `from()` animates **transform only** (y offset), NOT opacity.
- Code comment explicitly states: *"This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires — worst case it just doesn't slide."*
- Vault section (`min-height:92vh`) uses `start:'top 70%'` trigger — triggered by the section's top edge, not content visibility. Safe on mobile.
- `ScrollTrigger.refresh()` called on `window.load` and after 700ms to fix stuck positions after image/font load.

### `.vault` section
- `class="vault reveal"` — the `reveal` class here is a CSS `will-change` hint only, not an IntersectionObserver class.
- The vault background (`ds/sign.jpg`) is always visible via `position:absolute` — it cannot get stuck hidden.
- Content inside (`.vault-in > *`) animates with GSAP transform-only from `y:52`. Not opacity. Safe.

**No mobile black-gap risk detected.**
