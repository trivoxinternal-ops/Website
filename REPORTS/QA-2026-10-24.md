## 4. Hidden-content / Mobile Bugs

**Status: Clean**

**[data-reveal] pattern analysis:**

`motion.css` sets `[data-reveal]` to `opacity:0; transform:translateY(26px)` initially, revealed when `.in` is added.

`motion.js` uses `IntersectionObserver` with:
- `threshold: 0.15` (only 15% of the element must be visible — safe, triggers early)
- `rootMargin: '0px 0px -8% 0px'` (slight bottom offset)
- Fallback to `.classList.add('in')` for browsers without IntersectionObserver
- `prefers-reduced-motion: reduce` makes all elements immediately visible

**Threshold is 0.15 — no mobile trap risk.** Even a tall section only needs 15% visible, which happens well before it's fully in view.

**GSAP (scroll.js / inline) comment explicitly states:** "reveals animate TRANSFORM ONLY (no opacity). Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires — worst case it just doesn't slide."

**vault section** (`class="vault reveal"`) — `.reveal` is a will-change helper only (no opacity:0). Not vulnerable to get-stuck-hidden. ✅

No mobile black-gap risk detected.
