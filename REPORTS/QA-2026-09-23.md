## 4. Hidden-Content / Mobile Bugs

**Clean — no stuck-invisible risk.**

The `[data-reveal]` pattern (opacity:0 → .in) uses IntersectionObserver with `threshold: 0.15` and `rootMargin: '0px 0px -8% 0px'` (motion.js). A 15% threshold is low and safe — elements will trigger before needing to be mostly visible. Not the high-threshold (≥ 0.4) risk pattern.

GSAP ScrollTrigger (scroll.js / inline on index.html) animates **transform only** — opacity is never touched by GSAP. This is explicitly guarded against in the code comments:
> "reveals animate TRANSFORM ONLY (no opacity). Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires"

Reduced-motion fallback is present in both motion.css and motion.js — sets `opacity:1 !important` for `prefers-reduced-motion` users.

CSS `display:none` usages in site.css are all legitimate:
- `.nav-links{display:none}` at ≤780px — standard mobile nav collapse ✅  
- `.ledger .desc{display:none}` at ≤760px — deliberate mobile condensing ✅  
- `.clog .lr{opacity:0; animation:logIn forwards}` — log entries animate in and stay visible ✅
