## 4. Hidden-Content / Mobile Bugs

### ✅ Clean — no mobile visibility risk

**`[data-reveal]` pattern (motion.css):**
```css
[data-reveal] { opacity: 0; transform: translateY(26px); ... }
[data-reveal].in { opacity: 1; transform: none; }
```

**IntersectionObserver threshold (motion.js):**
```js
{ threshold: 0.15, rootMargin: '0px 0px -8% 0px' }
```
Threshold is **0.15** (only 15% of the element must be visible to trigger). This is a safe value — well below the ≥0.4 risk threshold. No mobile black-gap risk.

**GSAP ScrollTrigger (scroll.js and inline on index.html):**
Explicitly animates **transform only** (not opacity). The comment in both files reads: *"reveals animate TRANSFORM ONLY (no opacity). Opacity fade stays with motion.js [data-reveal], so nothing can ever get stuck invisible if a ScrollTrigger misfires."*

Both scripts also call `ScrollTrigger.refresh()` on window `load` and after 700ms timeout to correct stuck triggers on layout shift.

**Reduced-motion:** `@media (prefers-reduced-motion: reduce)` forces `opacity:1 !important` on all `[data-reveal]` elements, ensuring no-motion users always see all content. ✓
