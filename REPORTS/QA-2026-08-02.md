## 2. SEO / Social Meta

**Status: ⚠️ 2 issues**

### ✅ Clean pages
`index.html`, `ai-automation-toronto.html`, `ai-voice-agents.html`, `workflow-automation.html`, `case-car-deals-direct.html`, `case-clinic-receptionist.html` — all have title, meta description, canonical, og:title, og:description, og:image, twitter:card, twitter:image, viewport, favicon.

### ❌ Issue 1: `clinic-chatbot.html` — in sitemap, zero SEO meta, misleading title

- **Title:** `Northview Psychology — AI Receptionist` (fake client demo name, no TRIVOX branding)
- **Missing:** meta description, canonical, `og:title`, `og:description`, `og:image`, `twitter:card`, `twitter:image`
- **Missing:** `<meta name="robots" content="noindex">` — so search engines will crawl and try to index this
- **In sitemap:** Yes, at `priority: 0.6`

**Risk:** Google will index a page titled "Northview Psychology" with no description, no OG image, and no signal it's a TRIVOX demo. This confuses brand crawling and wastes crawl budget.

**Recommended fix (one of these):**
- Option A: Add `<meta name="robots" content="noindex, nofollow">` and remove from sitemap.xml.
- Option B: Add proper TRIVOX-branded meta: `<title>Clinic AI Receptionist Demo | TRIVOX AI</title>`, description, canonical, and og:* tags.

### ⚠️ Issue 2: `privacy.html` — missing canonical and meta description

- `privacy.html` is in the sitemap (priority 0.2) but has no `<link rel="canonical">` and no `<meta name="description">`. Also no og:* or twitter:* tags.
- Minor risk: duplicate-URL confusion if the page is ever linked with query strings.

**Recommended fix:** Add `<link rel="canonical" href="https://trivox.ca/privacy.html">` and a one-line meta description.

## 4. Hidden-Content / Mobile Bugs

**Status: ✅ Clean — no stuck-hidden risk**

**`[data-reveal]` system (motion.js + motion.css):**
- Initial state: `opacity:0; transform:translateY(26px)`
- Revealed by adding `.in` via IntersectionObserver
- **Threshold: `0.15`** (15% of element visible triggers reveal) with `rootMargin: '0px 0px -8% 0px'`
- This is a LOW, mobile-safe threshold — only 15% needs to be visible. No tall-element stuck-invisible risk.
- Reduced-motion: immediately adds `.in` to all reveals ✓
- No-JS fallback: `<noscript>` not needed; IE-era browsers get `.in` via the `else` branch ✓

**GSAP ScrollTrigger (scroll.js):**
- Comment explicitly notes: "reveals animate TRANSFORM ONLY (no opacity). Opacity fade stays with motion.js [data-reveal], so nothing can ever get stuck invisible if a ScrollTrigger misfires — worst case an element just doesn't slide."
- Two-layer separation is a deliberate, defensive pattern ✓

**`.vault reveal` class (index.html):**
- `class="reveal"` on the vault section — the `reveal` class in inline CSS only sets `will-change:transform,opacity`, NOT `opacity:0`. Section is always visible ✓

**Conclusion:** No mobile hidden-content bug. The threshold is safe; the opacity/transform split is sound.
