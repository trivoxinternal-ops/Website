## 4. Hidden Content / Mobile Bugs

**Status: ✅ CLEAN — No mobile stuck-hidden risk found**

### Reveal system analysis

`motion.css` sets:
```css
[data-reveal] { opacity: 0; transform: translateY(26px); }
[data-reveal].in { opacity: 1; transform: none; }
```

`motion.js` uses IntersectionObserver with:
```javascript
{ threshold: 0.15, rootMargin: '0px 0px -8% 0px' }
```

**Threshold 0.15 is safe on mobile.** Only 15% of an element needs to be visible before it reveals. No tall-section + high-threshold risk.

**The GSAP layer (scroll.js)** animates TRANSFORM ONLY, not opacity. The comments in both `scroll.js` and `index.html` explicitly document this safety invariant:

> "Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires."

Both files call `ScrollTrigger.refresh()` at `window.load` and via `setTimeout(700ms)` to handle layout-shift from fonts/images.

The `.vault` section uses class `.reveal` (not `data-reveal`), and its CSS just sets `will-change` — it is NOT hidden by default. ✅

**Conclusion:** The dual-layer motion system is well-designed. No mobile black-gap risk.
