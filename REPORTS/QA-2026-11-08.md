## 3. Accessibility Basics

**Result: Mostly clean, minor heading skips**

- All 11 pages have `<html lang="en">` ✓
- All 10 public pages have exactly one `<h1>` ✓ (clinic-chatbot has no headings — it's a chat widget)
- All `<img>` tags have non-empty `alt` attributes ✓

**⚠️ Heading level skips (h2 → h4, skipping h3):**

Affects: `case-car-deals-direct.html`, `case-clinic-receptionist.html`, `ai-automation-gta.html`, `ai-automation-mississauga.html`, `ai-automation-toronto.html`, `index.html`

The pattern is consistent: stat/outcome tiles (`.octiles`, `.vals`, `.out`) use `<h4>` directly inside a section under an `<h2>`, bypassing `<h3>`. Not a visual problem, but screenreaders and accessibility auditors will flag it. Consider changing those tile headings from `<h4>` to `<h3>`, or using `<strong>` or `<p>` if they're not semantic headings.

## 4. Hidden-Content / Mobile Bugs

**Result: CLEAN — no stuck-invisible risk found**

- **motion.js / `[data-reveal]`:** Uses IntersectionObserver with `threshold: 0.15`. An element triggers once 15% is in the viewport. Safe for mobile — even a tall element needs only a small slice visible. ✓
- **scroll.js / GSAP ScrollTrigger:** Uses `start: 'top 82%'` / `top 78%` / `top 85%` patterns. These animate `transform` only (never `opacity`). The comment in the source explicitly states: *"nothing can ever get stuck invisible if a ScrollTrigger misfires — worst case an element just doesn't slide."* ✓
- **`.vault.reveal` on index.html:** The `.reveal` class only sets `will-change: transform, opacity` in the inline CSS — it does NOT set `opacity: 0` or `visibility: hidden`. Not a hidden-on-load element. ✓
- **`.svc-body{opacity:0}`:** Service accordion body is hidden via CSS but revealed by click interaction (JS). Not a scroll-triggered element, no mobile risk. ✓
