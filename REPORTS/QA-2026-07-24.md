## 2. SEO / Social Meta

### ⚠️ ISSUE — clinic-chatbot.html: Missing ALL SEO and social meta

**Severity: Medium**

`clinic-chatbot.html` is in the sitemap (priority 0.6, `lastmod: 2026-06-21`) and will be crawled and indexed by Google. However it has **zero** SEO or social metadata:

- ❌ No `<meta name="description">`
- ❌ No `<link rel="canonical">`
- ❌ No `<meta property="og:title">`, `og:description`, `og:image`
- ❌ No `<meta name="twitter:card">`, `twitter:title`, `twitter:image`
- ❌ No `<meta name="robots" content="noindex">` (so Google WILL index it)

When shared on WhatsApp, Slack, or iMessage, it will show a blank preview. Google will auto-generate a snippet from whatever content it can find, likely just "Northview Psychology — AI Receptionist".

**Fix options:**
- **Preferred:** Add `<meta name="robots" content="noindex, follow">` since this is a client demo page, not a TRIVOX brand page. Then remove it from sitemap.xml.
- **Alternative:** Add proper TRIVOX meta (canonical, description, og:image) positioning it as a "demo build" page if you want it indexed.

## 4. Hidden-Content / Mobile Bugs

**Status: ✅ CLEAN — safe patterns in use**

### `[data-reveal]` / motion.js

`motion.css` sets `[data-reveal]` elements to `opacity:0` + `transform:translateY(26px)` initially. `motion.js` uses IntersectionObserver with:

```js
{ threshold: 0.15, rootMargin: '0px 0px -8% 0px' }
```

**threshold: 0.15 is well below the 0.4 mobile risk zone.** An element only needs 15% of itself visible to trigger. No tall `[data-reveal]` element at high threshold detected. Risk of stuck-invisible sections on mobile is low.

### GSAP (index.html)

The v2 GSAP scroll script animates **transform only** (not opacity) and explicitly states:
> "This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires"

Additionally, `ScrollTrigger.refresh()` is called twice after load (on `window.load` + a 700ms timeout) to catch layout shifts from fonts/images. Safe.

### vault section (index.html)

Uses class `reveal` (not `data-reveal`). The inline CSS defines `.reveal{will-change:transform,opacity}` — this is only a browser performance hint, not a visibility state. Content is always visible. ✅

### prefers-reduced-motion

`motion.css` properly overrides: `[data-reveal]{ opacity:1 !important; transform:none !important; }` for reduced-motion users. ✅
