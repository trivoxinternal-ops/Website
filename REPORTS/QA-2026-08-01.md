## 4. Hidden-content / Mobile Bugs

**Status: ✅ CLEAN — reveal system is mobile-safe**

### Reveal pattern analysis

**motion.css** sets `[data-reveal]` to `opacity:0; transform:translateY(26px)` initially.

**motion.js** uses:
```js
new IntersectionObserver(callback, { threshold: 0.15, rootMargin: '0px 0px -8% 0px' })
```

**Assessment:** threshold of 0.15 (15%) is mobile-safe. Even a full-viewport-height section only needs 15% visible to fire. No risk of sections staying permanently hidden due to a high threshold on mobile.

**GSAP / scroll.js** (sub-pages): Animates transform only, NOT opacity. The code explicitly documents: *"reveals animate TRANSFORM ONLY (no opacity). Opacity fade stays with motion.js [data-reveal], so nothing can ever get stuck invisible if a ScrollTrigger misfires."* ✅ Belt-and-suspenders approach — no stuck-invisible risk.

**`section.vault.reveal`** (index.html): Has class `reveal` but NOT the `[data-reveal]` attribute. CSS `.reveal` only sets `will-change: transform, opacity` — no hidden state. Not affected by motion.js. ✅

**`prefers-reduced-motion`**: Handled correctly in both motion.css (overrides all hidden states to visible) and motion.js (marks all reveals visible immediately). ✅

**`.svc-body` (accordion):** Hidden by default (`opacity:0; grid-template-rows:0fr`) and revealed on click by the accordion JS. This is intentional interactive behavior, not a bug. ✅
