## 4. Hidden-Content / Mobile Bugs

**Result: ✅ CLEAN — no mobile black gap risk**

### Reveal pattern analysis

**`[data-reveal]` (motion.css + motion.js):**
- Starts at `opacity:0; transform:translateY(26px)`
- Revealed by IntersectionObserver at `threshold:0.15` with `rootMargin:'0px 0px -8% 0px'`
- **Threshold of 0.15 is safe** — elements trigger at 15% visibility, so even tall sections on small phones will unlock as soon as a small portion scrolls into view

**GSAP ScrollTrigger (index.html):**
- Code comment explicitly notes: *"reveals animate TRANSFORM ONLY (no opacity). Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires."*
- GSAP triggers at `start:'top 82%'` or `start:'top 85%'` — shallow, safe for mobile
- Vault content uses `start:'top 70%'` — also within safe mobile range

**`.vault.reveal` section (index.html):**
- Has class `.reveal` (not `[data-reveal]`)
- `.reveal` CSS: only `will-change:transform,opacity` — does NOT set opacity:0
- Vault is **always visible**; GSAP only translates inner elements from y:52
- No risk of permanent invisibility

**Accordion (`.svc-body`):**
- Uses `grid-template-rows:0fr; opacity:0` for closed state
- Only revealed on user click, not scroll-triggered
- Not a mobile reveal risk

**Conclusion:** No element can get permanently stuck invisible. The dual-layer design (motion.js for opacity, GSAP for transform only) is a solid pattern.
