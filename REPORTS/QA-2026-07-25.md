## 4. Hidden Content / Mobile Bugs

**Result: ✅ CLEAN — design intentionally prevents stuck-hidden**

- `[data-reveal]` elements start at `opacity:0`, revealed when IntersectionObserver fires the `.in` class.
- **Threshold: 0.15** (15% visible triggers reveal) — well below the dangerous ≥0.4 range that causes mobile stuck-hidden bugs.
- `rootMargin: '0px 0px -8% 0px'` — fires slightly before full entry. Safe on all viewport sizes.
- The scroll reveal pattern correctly separates concerns:
  - **Opacity**: IntersectionObserver (`motion.js`) — triggers at 15%, very forgiving.
  - **Transforms (GSAP)**: ScrollTrigger handles slide-in only. If GSAP misfires, content stays visible; only the slide animation is lost.
- The code comment in both `scroll.js` and `index.html` inline script explicitly documents this design decision.
- `ScrollTrigger.refresh()` is called on `load` and after 700ms to handle layout shift from fonts/images.
- Reduced-motion: `[data-reveal]` gets `opacity:1 !important` via CSS + JS adds `.in` immediately. ✅
- The `.vault` section (`min-height: 92vh`) uses class `reveal` (not `data-reveal`), so IntersectionObserver does NOT control its opacity — it's always visible. GSAP handles only transform animations on `.vault-in > *`. ✅

No mobile stuck-hidden risk found.
