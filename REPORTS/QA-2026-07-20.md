## 4. Hidden-Content / Mobile Bugs

**Status: ✅ CLEAN — reveal system is well-architected**

**`[data-reveal]` pattern** (used on all main pages):
- CSS starts elements at `opacity:0; transform:translateY(26px)`.
- `motion.js` uses `IntersectionObserver` with **threshold: 0.15** and `rootMargin: '0px 0px -8% 0px'`.
- **Threshold 0.15 is safe on mobile** — only 15% of the element needs to be in view. Even a 1,000px section only needs 150px visible. No risk of elements staying hidden due to an aggressive threshold.
- Reduced-motion: if `prefers-reduced-motion` is set, `motion.js` immediately adds `.in` to all `[data-reveal]` elements (bypasses animation entirely). Also covered in CSS with `[data-reveal] { opacity:1 !important; ... }`.
- NoJS fallback: if `IntersectionObserver` is unavailable, `motion.js` falls back to adding `.in` to all elements immediately.
- GSAP / ScrollTrigger (on sub-pages): animates `transform` only (not opacity), so even if GSAP misfires on mobile, elements remain visible via the `[data-reveal]` opacity path. Code comment confirms this is intentional architecture.
- `ScrollTrigger.refresh()` called on `window.load` and after 700ms timeout (guards against late-loading fonts/images shifting layout).

**`.vault` section (index.html):** Has `class="vault reveal"` — the `.reveal` class only sets `will-change`, does NOT set opacity:0. The vault starts visible. No hidden-content risk.

No mobile hidden-content bugs found.
