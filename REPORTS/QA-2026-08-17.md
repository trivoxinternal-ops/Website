## 4. Hidden-Content / Mobile Bugs

### ✅ Reveal system is mobile-safe
`[data-reveal]` elements start `opacity:0; transform:translateY(26px)` and are revealed via `IntersectionObserver` in `motion.js` with **threshold: 0.15** and **rootMargin: '0px 0px -8% 0px'**. The low threshold (15%) means even partially-visible elements trigger reveal — no risk of tall sections staying hidden on mobile.

**Important note from inline comment in index.html and scroll.js:**
> "IMPORTANT: reveals animate TRANSFORM ONLY (no opacity). Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires."

The architecture correctly separates opacity (motion.js/IntersectionObserver) from transform (GSAP/ScrollTrigger). If GSAP fails to load, elements simply don't slide but are fully visible. ✅

### ✅ Vault section (`#work`)
Uses `class="vault reveal"` (not `[data-reveal]`). The `.reveal` class in the inline `<style>` only sets `will-change: transform, opacity` — no hidden state. Vault is visible without JS. ✅

### ✅ `prefers-reduced-motion` respected
Both `motion.css` and all JS scripts check for `prefers-reduced-motion` and skip animations, immediately marking all reveal elements as visible. ✅
