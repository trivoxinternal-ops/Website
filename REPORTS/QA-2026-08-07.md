## 3. Accessibility Basics

**Main pages: Clean.**

All pages have `<html lang="en">`. Every navigational `<img>` has a non-empty `alt`. Each content page has exactly one `<h1>`. Heading levels are used consistently.

### ⚠️ ISSUE 3 — clinic-chatbot.html: `user-scalable=no` blocks zoom
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
```
Preventing user zoom is a WCAG 1.4.4 (Level AA) violation and can affect accessibility compliance.  
**Recommendation:** Remove `maximum-scale=1.0, user-scalable=no` or replace with `user-scalable=yes`.

## 4. Hidden-Content / Mobile Bugs

**Clean.** No stuck-invisible risk found.

- **`[data-reveal]` pattern** (`motion.js`): Uses `IntersectionObserver` with `threshold: 0.15` (15%) and `rootMargin: '0px 0px -8% 0px'`. The low threshold means even tall elements trigger reliably on mobile — no concern here.
- **GSAP animations** (`index.html` inline, `ds/scroll.js` on sub-pages): All GSAP reveals animate **transform only** (no opacity). Opacity is handled exclusively by the CSS+IntersectionObserver `[data-reveal]` layer. If a ScrollTrigger misfires, worst case is the element doesn't slide in — it won't get stuck invisible. This is a well-designed defensive pattern.
- **`.vault section`** (`index.html`): Has `class="reveal"` (not `data-reveal`). The `.reveal` class is only `will-change: transform, opacity` — no opacity:0. GSAP animates children's transforms only. No stuck-invisible risk.
- **`.svc-body` accordion** (`index.html`): Uses `grid-template-rows: 0fr` to collapse — this is a toggle on click, not a scroll reveal, and JavaScript is present to handle it. Not a mobile bug.
