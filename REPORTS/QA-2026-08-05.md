## 4. Hidden-Content / Mobile Bugs

**Status: ✅ Clean — reveal system is safe**

### Reveal architecture examined:

**`[data-reveal]` elements** (motion.css/motion.js):
- Starts at `opacity:0; transform:translateY(26px)`
- IntersectionObserver threshold: **0.15** (only 15% visible needed to reveal) — safe for tall elements
- `rootMargin: '0px 0px -8% 0px'` — conservative, won't delay reveals
- Fallback: if no IntersectionObserver, all elements instantly get `.in` class (visible)
- Reduced-motion: elements are immediately `.in` (visible) — ✓

**GSAP ScrollTrigger** (scroll.js / index.html inline):
- Critical design decision noted in comments: *"reveals animate TRANSFORM ONLY (no opacity). Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires."*
- This means even if GSAP fails to load (CDN blocked, slow connection), sections remain visible — just don't slide in. ✓
- ScrollTrigger thresholds: `.band .head` at `top 82%`, `.product` at `top 85%` — reasonable.
- `ScrollTrigger.refresh()` called both on `window load` and after 700ms timeout (guards layout shift). ✓

**No mobile invisible-content risk found.** The dual-layer approach (IntersectionObserver at 15% for opacity, GSAP for transform only) is well-architected.

**⚠️ `href="#"` for "Hours" links — 4 pages:**

The contact section on 4 pages uses a dead anchor for the hours text:
```html
<span><span class="lbl">Hours</span><a href="#">Mon–Fri, 9–6 EST</a></span>
```
- `index.html` line 432
- `ai-automation-toronto.html` line 219
- `ai-voice-agents.html` line 200
- `workflow-automation.html` line 213

Clicking "Mon–Fri, 9–6 EST" scrolls the page to the top. This is misleading UX — hours is not a link to anything. Should either be plain text (remove the `<a>`) or link to a real anchor/contact section.
