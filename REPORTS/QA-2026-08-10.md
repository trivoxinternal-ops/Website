## 4. Hidden-Content / Mobile Reveal Bugs

**Status: ✅ Clean — well-engineered**

The site uses a two-layer reveal system:
- **Layer 1 — `motion.js`:** `[data-reveal]` elements start at `opacity:0 + translateY(26px)`. IntersectionObserver threshold is **0.15** (15%), rootMargin `0px 0px -8% 0px`. Threshold is safe — no risk of a tall element never crossing it on mobile.
- **Layer 2 — `scroll.js` / GSAP ScrollTrigger:** Animates **transform only**, explicitly not opacity. Comments in both `scroll.js` and `index.html` confirm: *"Opacity fade is handled by motion.js [data-reveal]. This guarantees no element can ever get stuck invisible if a ScrollTrigger misfires."*
- `[data-reveal]` on `prefers-reduced-motion` immediately adds `.in` class — no stuck-invisible risk.
- `.vault.reveal` on index.html: the `.reveal` class only sets `will-change:transform,opacity` (no `opacity:0`) — this section is never initially hidden.

No high-threshold IntersectionObserver, no sections that could get stuck invisible on mobile. ✅
