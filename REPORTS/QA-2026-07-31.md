## 2. SEO / Social Meta

### ✅ Clean (6/8 pages)
index.html, ai-automation-toronto.html, ai-voice-agents.html, case-clinic-receptionist.html, case-car-deals-direct.html, workflow-automation.html — all have: `<title>`, meta description, canonical, og:title, og:description, og:image, twitter:card, twitter:image, viewport, favicon/apple-touch-icon.

### ⚠️ clinic-chatbot.html — Missing all SEO / social meta (Medium)

The page has only a `<title>Northview Psychology — AI Receptionist</title>` and a favicon. Missing:
- No `<meta name="description">`
- No `<link rel="canonical">`
- No `og:title`, `og:description`, `og:image`
- No `twitter:card`, `twitter:image`

This page is publicly accessible in the repo and presumably served live. If shared (e.g., via a social link or a client sending it to someone), there will be no social card preview. Additionally, crawlers will index it without a description.

**Fix:** Either add a minimal `<meta name="robots" content="noindex">` + `<meta name="description">`, or add a proper social meta block if the page is meant to be findable.

### ⚠️ privacy.html — Missing all SEO / social meta (Minor)

Same gap: has `<title>` and favicon, but no description, canonical, or social meta. Privacy pages are often intentionally thin on SEO, but a `noindex` meta and a description are still best practice.

**Fix:** Add `<meta name="robots" content="noindex, follow">` and a short `<meta name="description">` at minimum.

## 4. Hidden-content / Mobile Bugs — ✅ Clean

Reveal system analysis:

- **`[data-reveal]`** (motion.css): starts at `opacity:0; transform:translateY(26px)`. Revealed by motion.js IntersectionObserver with `threshold: 0.15` and `rootMargin: '0px 0px -8% 0px'`. This 15% threshold is mobile-safe — no element needs 40%+ intersection to trigger.
- **GSAP animations** (scroll.js, index.html inline): animate `transform` only (y, xPercent) — no opacity. This is explicitly commented in both files: *"IMPORTANT: reveals animate TRANSFORM ONLY (no opacity). Opacity fade stays with motion.js [data-reveal], so nothing can ever get stuck invisible if a ScrollTrigger misfires."* Robust design.
- **`.svc-body` accordion** (index.html): `opacity:0` by design for collapsed state. JS adds/removes `.open` class reliably. Not a stuck-invisible risk.
- **`.vault.reveal`** (index.html): uses `.reveal` class (not `[data-reveal]`) which only sets `will-change`. Not opacity-hidden. GSAP animates transform only. Safe.
- `ScrollTrigger.refresh()` is called both on `load` and after 700ms timeout, preventing layout-shift stuck-triggers.

No mobile-specific hidden-content bugs found.

**`href="#"` dead-links on 4 pages (Minor)**

In the CTA / contacts section, the "Hours" entry is coded as:
```html
<a href="#">Mon–Fri, 9–6 EST</a>
```
This is a non-functional anchor on: index.html, ai-automation-toronto.html, ai-voice-agents.html, workflow-automation.html.

It renders without visual error but clicking it scrolls to the top of the page. This is not a broken link per se, but it's an unfulfilled user interaction.

**Fix options:** Remove the `<a>` tag and render as plain text (`<span>`), or link to `#faq` or a contact section.
